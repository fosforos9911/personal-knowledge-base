# Level 0：工程骨架

状态：已完成

## 本阶段内容

- FastAPI 应用入口和生命周期；
- 配置对象与本地数据目录初始化；
- SQLite 数据库和基础文档表；
- `/api/health` 健康检查；
- `/api/modules` 可插拔导航契约；
- Vue 前端布局和页面路由占位；
- 最小数据库、健康检查和模块契约测试；
- Git 忽略规则，避免密钥、文档数据、依赖包和缓存进入版本库。

## 这一阶段到底是什么

本阶段是“可运行骨架 + 最小启动编排”，不是完整知识库业务。它先解决三个基础问题：

1. 应用从哪里启动：`app/main.py` 的 `lifespan()` 按“目录初始化 → 数据库初始化 → 接收请求”编排；
2. 数据放在哪里：`app/config.py` 集中管理路径，`app/db.py` 只保存可检索的元数据；
3. 页面如何扩展：`/api/modules` 返回导航契约，前端不把未来模块写死在主布局逻辑里。

## 为什么现在就设计 documents 表

它不是为了提前完成全部业务，而是为了固定一个最小稳定边界：文档必须有唯一 ID、标题、分类、行业、可信等级、阶段和状态。后续导入、检索、问答都会依赖这个 ID 找到原文和引用位置。字段先保守保留，真正的正文、分块、向量和图谱关系将在后续迁移中增加。

## 文件与函数的决策链

```text
用户启动应用
  -> main.lifespan()
  -> config.settings.ensure_directories()
  -> db.initialize_database()
  -> router.health()/router.modules()
  -> 后续 services.document_service/search_service/chat_service
```

函数按职责拆分，而不是按“一个功能一个大文件”堆叠：配置函数只处理配置，数据库函数只处理连接和 schema，路由函数只处理 HTTP。这样 Level 1 增加文档服务时，可以把上传、解析和状态变更放到 service，不破坏启动流程。
